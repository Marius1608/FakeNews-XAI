# FakeNews-XAI

**Explainable detection of temporal inconsistencies in political news using Temporal Knowledge Graphs and a coherence score (TCS).**

Bachelor's Thesis — Technical University of Cluj-Napoca (UTCN), Faculty of Automation and Computer Science, 2026  
Author: Marius Pantea | Supervisor: Prof. Adrian Groza | Co-supervisor: Conf. Ioana Chereș

---

## Overview

The system analyzes political news articles and computes a **Temporal Coherence Score (TCS)** — a value in [0, 1] that quantifies the temporal coherence of an article. A high score indicates a temporally consistent article; a low score signals inconsistencies that may suggest misinformation.

In addition to the score, the system produces:
- a list of detected inconsistencies (type, severity, description, evidence)
- a chronological timeline of extracted facts
- a natural language explanation generated by a local LLM (XAI)

**Main contribution:** the TCS metric and the C1→C2→C3→C4 pipeline that computes it through five-level hierarchical verification against external sources (Reference KG, Neo4j, Wikidata, RSS).

## System Architecture (C1–C4)

```
Political news article
         |
         v
[C1 — Temporal Extraction]
  Pipeline A: spaCy en_core_web_trf     (deterministic, ~10-20s/article)
  Pipeline B: Qwen3-1.7B (HuggingFace)  (LLM, few-shot,  ~40s/article)
         |
         v  TemporalFacts (subject, predicate, object, time)
         |
         v
[C2 — TKG Construction]
  TKGBuilder: filter (confidence ≥ 0.3, temporal anchor) → deduplicate → insert
  TemporalKnowledgeGraph (networkx MultiDiGraph) — per article, in-memory
  Neo4j Community Edition                         — persistent, cross-article
         |
         v  TKG
         |
         v
[C3a — Internal Verification — 8 checkers (V1-V8)]
  V1: Temporal cycles (networkx.find_cycle)                    — HIGH
  V2: Causal violations (effect before cause)                  — HIGH
  V3: Inverted intervals + implausible durations               — MEDIUM / LOW
  V4: Factual contradictions (same role, different subjects, overlap) — HIGH
  V5: Implicit contradictions (mandate before election, 180-day buffer) — MEDIUM
  V6: Future event reported as past                            — HIGH
  V7: Incompatible simultaneous roles (9 predefined sets)      — MEDIUM / LOW
  V8: Action before taking office (90-day buffer)              — HIGH

[C3b — External Verification — 5 hierarchical levels]
  L1: Local Reference KG (1,233 facts: political mandates + 64 canonical events + 22 manual)
  L2: Neo4j cache (cross-article, active when NEO4J_ENABLED=true)
  L3: Wikidata SPARQL live (P39, P463)
  L4: Wikidata inverse query (interval validation)
  L5: RSS Stream (8 active political feeds, 30-min cache)
         |
         v  Inconsistencies (type, severity, evidence)
         |
         v
[C4 — TCS Computation + Explainability]
  TCS = (1 - penalty_ratio) × score_coherence × (0.85 + 0.15 × coverage_factor)

  penalty_ratio    = sum(severity_weight × inconsistency) / max_possible_penalty
                     max_possible_penalty = n_claims × 1.5
  score_coherence  = 1 - (MEDIUM+ inconsistencies / temporal_relations)
  coverage_factor  = facts_verified / facts_total  (0.5 if facts_total = 0)

  Severity weights: LOW=0.0  MEDIUM=0.3  HIGH=1.0  CRITICAL=1.5
  Predicted FAKE if TCS < FAKE_THRESHOLD (default: 0.75)
  TCS = 0.5 if n_claims = 0 (Insufficient Temporal Data)

  XAI: Qwen3-1.7B generates a natural language explanation
  XAI Fallback: static templates per inconsistency type
         |
         v
OUTPUT: TCS Score + Label + Inconsistency List + Timeline + AI Explanation
```

## TCS Score Interpretation

| Range | Label | Meaning |
|---|---|---|
| 0.8 – 1.0 | Highly Consistent (Likely True) | Temporally coherent facts |
| 0.5 – 0.8 | Moderately Consistent | Minor inconsistencies |
| 0.2 – 0.5 | Multiple Inconsistencies (Suspicious) | Multiple contradictions |
| 0.0 – 0.2 | Severe Violations (Likely Fake) | Critical inconsistencies |
| = 0.5 (special) | Insufficient Temporal Data | No temporal facts extracted |

## Evaluation Results

### Main benchmark (150 synthetic articles, 75T/75F)

| Configuration | P | R | F1 | Acc | FP | Sep. |
|---|---|---|---|---|---|---|
| Baseline (Jun 2, thr=0.70) | 0.714 | 0.227 | 0.345 | 0.620 | 4 | +0.129 |
| Best iteration (Jun 12, thr=0.70) | 0.706 | 0.273 | 0.393 | 0.630 | 5 | +0.151 |
| **Final (Jun 19, thr=0.75)** | **0.909** | **0.227** | **0.364** | **0.650** | **1** | **+0.133** |

avg TCS TRUE = 0.880 | avg TCS FAKE = 0.747 | Separation = +0.133

### Threshold sweep (final configuration)

| Threshold | P | R | F1 | Acc |
|---|---|---|---|---|
| 0.50 | 0.833 | 0.227 | 0.357 | 0.640 |
| 0.55 | 0.846 | 0.250 | 0.386 | 0.650 |
| 0.65 | 0.750 | 0.273 | 0.400 | 0.640 |
| 0.70 | 0.706 | 0.273 | 0.393 | 0.630 |
| **0.75** | **0.909** | **0.227** | **0.364** | **0.650** |
| 0.80 (F1-optimal) | 0.552 | 0.364 | 0.438 | 0.590 |

### Baseline classifiers (TF-IDF, 5-fold CV)

| Model | P | R | F1 | Acc |
|---|---|---|---|---|
| Logistic Regression | 0.783 | 0.181 | 0.280 | 0.610 |
| Random Forest | 0.701 | 0.500 | 0.572 | 0.680 |
| SVM-linear | 0.777 | 0.436 | 0.535 | 0.680 |

RF and SVM outperform TCS on F1 on a small stylistically homogeneous set. TCS provides temporal explainability and external verification that lexical baselines cannot — baselines cannot identify which specific inconsistency exists or why.

### External dataset evaluation

| Dataset | P | R | F1 | Conclusion |
|---|---|---|---|---|
| ISOT (50T/50F, political) | 0.000 | 0.000 | 0.000 | Fake news via emotional language, not temporal |
| RAGuard (50T/50F, political) | 1.000 | 0.020 | 0.039 | Short claims with no temporal anchoring |

TCS is a specialized metric for temporal inconsistencies in narrative political news — not a general-purpose fake news detector.

## Installation

### Step 1 — Clone the repository

```bash
git clone https://github.com/Marius1608/FakeNews-XAI.git
cd FakeNews-XAI
```

### Step 2 — Create a Python virtual environment

```bash
python -m venv venv

# Activate — Windows (Git Bash)
source venv/Scripts/activate

# Activate — Linux / macOS
source venv/bin/activate
```

### Step 3 — Install Python dependencies

```bash
pip install -r requirements.txt
```

> **Windows note:** if `pip install` fails on `torch`, first install PyTorch manually from [pytorch.org](https://pytorch.org/get-started/locally/) for your CUDA version or CPU.

### Step 4 — Download the spaCy model (Pipeline A)

```bash
python -m spacy download en_core_web_trf
```

`en_core_web_trf` (~500 MB) is a RoBERTa-based transformer model used for NER and dependency parsing in Pipeline A.

> **Faster alternative (CPU-only):** `python -m spacy download en_core_web_sm` (~12 MB), with reduced extraction accuracy.

### Step 5 — Download Qwen3-1.7B (Pipeline B / XAI — optional)

Qwen3-1.7B is downloaded **automatically** by HuggingFace Hub on the first call to Pipeline B or the XAI explainer. No manual step is required. Model size is ~3 GB.

To pre-download it explicitly:

```bash
python -c "from transformers import AutoModelForCausalLM, AutoTokenizer; AutoTokenizer.from_pretrained('Qwen/Qwen3-1.7B'); AutoModelForCausalLM.from_pretrained('Qwen/Qwen3-1.7B')"
```

If Qwen3 is unavailable (no GPU or insufficient memory), the system continues to work with Pipeline A and static XAI templates.

### Step 6 — Configure environment variables

```bash
cp .env.example .env
# Edit .env to change ports, models, or enable Neo4j if needed.
# Default values work out of the box.
```

### Step 7 — (Optional) Set up Neo4j

Neo4j is optional. Without it the system runs fully (L1, L3, L4, L5 remain active), but L2 (cross-article cache) and HITL verification are unavailable.

**Option A — Neo4j Desktop:** download from [neo4j.com/download](https://neo4j.com/download/), create a local database, and start it.

**Option B — Docker:**

```bash
docker run -d \
  --name neo4j \
  -p 7687:7687 -p 7474:7474 \
  -e NEO4J_AUTH=neo4j/your_password \
  neo4j:community
```

Then set in `.env`:

```
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=your_password
NEO4J_DATABASE=neo4j
NEO4J_ENABLED=true
```

## Starting the System

### Option 1 — Automatic startup script (recommended)

```bash
bash start.sh
```

The script:
- checks and downloads any missing spaCy models
- detects whether Neo4j is running and sets `NEO4J_ENABLED` accordingly
- activates the Python virtual environment
- starts the FastAPI backend on port 8000
- starts the React frontend on port 3000
- prints a summary of active components

> **Windows (PowerShell):** run `bash start.sh` from Git Bash, or `wsl bash start.sh` if you have WSL.

**Terminal 1 — FastAPI Backend**

```bash
source venv/Scripts/activate   # Windows Git Bash

```

**Terminal 2 — React Frontend**

```bash
cd frontend
```

## Usage

### Web interface

The interface has four main tabs:

| Tab | Functionality |
|---|---|
| **Analyze** | Analyze an article entered as text or uploaded as a file (PDF, DOCX, TXT); select pipeline (A/B), publication date, Wikidata/RSS options |
| **Compare** | Compare Pipeline A vs. Pipeline B on the same article; shows score delta and agreement level |
| **Batch** | Analyze multiple articles at once; optional Neo4j persistence and cross-article verification |
| **History** | Browse articles saved in Neo4j (requires `NEO4J_ENABLED=true` and `persist=true`) |

**Visualizations available per article:**
- Circular TCS score display with coherence label
- Inconsistency list with type, severity, description, and evidence
- Chronological fact timeline
- Force-directed temporal knowledge graph
- Highlighted article text with per-sentence fact and inconsistency annotations
- LLM-generated explanation (when Qwen3 is available)

### Analyzing an article via the API

**POST `/analyze` request:**

```bash
curl -X POST http://localhost:8000/analyze \
  -H "Content-Type: application/json" \
  -d '{
    "text": "Obama served as President of the United States from January 2009 to January 2017...",
    "title": "Obama Presidency",
    "publication_date": "2024-01-01",
    "pipeline": "spacy",
    "use_wikidata": true,
    "persist": false
  }'
```

**Response (simplified):**

```json
{
  "score": 0.923,
  "label": "Highly Consistent (Likely True)",
  "summary": "The article's temporal claims are highly consistent (TCS = 0.92). Out of 5 temporal claims, 0 inconsistencies were detected.",
  "n_claims": 5,
  "n_inconsistencies": 0,
  "coherence_factor": 1.0,
  "inconsistency_details": [],
  "fact_annotations": [...],
  "timeline": [...],
  "pipeline": "spacy",
  "processing_time_ms": 12340.5,
  "llm_explanation": "The article presents a temporally coherent narrative..."
}
```

**`/analyze` request parameters:**

| Parameter | Type | Default | Description |
|---|---|---|---|
| `text` | string | required | Article text (min. 20 characters) |
| `title` | string | `""` | Article title (auto-generated from first words if empty) |
| `publication_date` | string | `null` | Publication date in `YYYY-MM-DD` format |
| `pipeline` | string | `"spacy"` | Extraction pipeline: `"spacy"` (A) or `"llm"` (B) |
| `model` | string | `null` | Specific model (default: `en_core_web_trf` / `Qwen/Qwen3-1.7B`) |
| `persist` | bool | `false` | Save facts to Neo4j for cross-article analysis (requires `NEO4J_ENABLED=true`) |
| `use_wikidata` | bool | `true` | Enable live Wikidata SPARQL verification (L3+L4) |
| `use_rss` | bool | `false` | Enable RSS Stream verification (L5) |
| `use_web_search` | bool | `false` | Enable Wikipedia REST API fallback (disabled in production) |

## Deployment (HuggingFace Spaces)

The system is ready for Docker-based deployment on HuggingFace Spaces:

```bash
# Local test build
docker build -t fakenews-xai .
docker run -p 7860:7860 -e HF_SPACES=true fakenews-xai
```

The Dockerfile uses a two-stage build:
1. **Stage 1** (`node:20-slim`): compiles the React frontend via `npm run build`
2. **Stage 2** (`python:3.11-slim`): installs Python deps, downloads the spaCy model, copies the backend and the compiled React build

On HuggingFace Spaces, the FastAPI backend serves both the API routes (`/analyze`, `/health`, etc.) and the compiled React SPA (catch-all `/{path}`), all on port 7860.

Neo4j Aura credentials (if used) are injected at runtime via Spaces Secrets as environment variables — they are never hardcoded in the image.

## Evaluated and Rejected Alternatives

| Alternative | Reason for rejection |
|---|---|
| REBEL-large (Pipeline C) | F1=0.038 in isolation, net negative on benchmark |
| DeepKE | Windows-incompatible (jieba dependency), models 13B+ |
| Ollama / llama3:8b | Replaced by Qwen3-1.7B (smaller footprint, no external server) |
| flan-t5-base/large | seq2seq architecture, cannot generate structured JSON |
| Wikipedia REST API | False positives in production, lower F1 |
| Stanza | Inferior dependency parsing vs. spaCy on English political text |
| QLoRA fine-tuning | Infrastructure built, not executed (future work) |
| LIAR2 / Kaggle | TCS=0.5 majority (short claims with no temporal anchoring) |
| DuckDuckGo Instant Answer | Zero useful results for political entities |
